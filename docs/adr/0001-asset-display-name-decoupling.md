# ADR-0001：资产展示名称与原始文件名及 TOS 对象解耦

- 状态：Accepted
- 日期：2026-08-04

## 背景

现有 `Asset.filename` 同时承担上传追溯和界面展示。用户需要在不改变原始文件、存储路径和历史引用的前提下编辑图片名称。直接修改 `filename` 会丢失原始文件名语义，也容易让人误以为 TOS 对象已重命名。

## 决策

- 新增 `Asset.display_name` 作为可编辑展示名称。
- `Asset.filename` 固定保留上传时完整原始文件名。
- `Asset.tos_key` 固定保留创建时存储定位，不因展示名称变化。
- 资产 ID 是唯一标识；展示名称允许重复，不建立唯一约束。
- 旧资产按原始文件名去掉最后一个扩展名回填展示名称。
- 改名操作写独立审计日志。

## 备选方案

1. 直接修改 `filename`：字段少，但破坏原始文件追溯，并混淆存储对象是否被重命名。
2. 修改 `filename` 并同步移动 TOS 对象：实现和失败补偿复杂，可能破坏签名 URL、快照和历史引用。
3. 把展示名放入 `metadata_json`：迁移简单，但类型、校验、搜索和索引能力弱，长期维护成本高。

## 结果

- 改名成为低风险元数据更新，不触碰图片二进制和引用关系。
- API 在迁移期需同时返回 `display_name` 与 `filename`。
- 所有新 UI 必须展示 `display_name`，需要追溯时单独呈现 `filename`。
- 数据库需新增字段并执行回填迁移；历史调用方可继续读取 `filename`。
